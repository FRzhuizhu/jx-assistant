# 会话级组件配置（合并层）——改动说明与验证步骤

日期：2026-11-08　范围：`sessioncx.go` / `sessioncxcfg.go`（新）/ `components.go`
（清单响应带 cfg）/ `server.go`（路由 + call_api 目录）/ `web/cx.js`（读取通道 +
装配）/ `web/app-cxsession.js`（浮窗 UI）/ `web/index.html` / `web/style.css` /
文档（`AGENT.md`、`组件/README.md`）

## 一、机制（定稿方案落地）

**统一「会话视角配置合并层」**：会话覆盖从「组件开关（布尔）」扩成「任意配置项
KV」（`SessionOverrides.Cfg[组件id][键] = 值`，另有 `CfgScope` 总开关与
`CfgFollow` 显式跟随标记）；组件配置的读取通道上按「**会话覆盖 > 全局值**」合并
喂给组件——**组件零改动**，它读到的永远是该会话视角的值。

- **组件配置读取通道 = 组件自己的 localStorage 命名空间 `cx:<组件id>:*`**：
  `web/cx.js` 在页面初始化时装一层代理（`_installCfgChannel`），只拦
  `getItem / setItem / removeItem` 三个动词、只认 `cx:<组件id>:` 这层前缀，
  其它键（`jx.*`、别的前缀）原样透传。
  - 会话独立：读命中会话覆盖、未覆盖的键回落到全局值；写只进会话覆盖；
    写进去的值与全局值相同则不记覆盖（与既有「拨回全局＝删记录」同一口径）。
  - 跟随全局 / 没有会话 / 总开关关：读写全部透传真存储（原行为一字不改）。
  - **全局设置页开着时不走会话视角**（`_cfgBypassNow` 看 `#settings` 是否可见）：
    那里的读写就是全局值，两套视角不串。
- **全部组件全部设置自动支持**：不搞 manifest 声明，机制按命名空间自动覆盖；
  以后新组件按同一命名空间存偏好即自动获得会话化（写进 `组件/README.md` 硬规矩 7）。
- 全局值仍存在组件自己的存储里（独立不动）；覆盖统一存会话附属数据
  （`sessdata:cx-overrides:<会话id>`，随会话删除清理）。
- 装配：`GET /api/components?s=<会话id>` 的响应顺带带 `cfg`（总开关 + 每组件
  覆盖），`cx.js` 在注入组件前先就位，于是组件的 `init` 第一口读到的就是会话
  视角；切会话时把已装组件整段卸掉按新会话配置重装（`refresh()` 里
  `sessionChanged` 分支）。

## 二、UI（用户定稿）

浮窗（对话输入区加号菜单「本对话的组件与插件」）组件页：

- **每行两个开关**：上＝本对话启用/停用该组件（行级启停，原有能力，独立生效）；
  下＝该组件设置「会话独立 / 跟随全局」（`title` + 行末 10.5px 小字：启用/独立、
  启用/跟随）。总开关关着时下开关禁用。
- **底部总开关**「本对话使用独立的组件设置」（保存/取消旁）：
  - 开＝一键切全场：全场进入会话独立（缺省每行独立，覆盖为空＝值全来自全局）；
  - **关＝整行完全回归全局**：每行的配置覆盖 `Cfg`/`CfgFollow` 与行级启停覆盖
    `Components` **一起清空**，回到全局状态（总开关=完全回归，行级=细粒度）。
- 行级下开关拨回「跟随全局」＝删该组件的配置记录（恢复语义），并热重装该组件
  让它立刻按全局值重读；总开关切换则重装全部已启用组件。
- 组件注册的设置区（`CX.registerSettings`）照常在浮窗里展示：会话独立时改动
  写进本对话，跟随全局时改动就是全局值（顶部提示已说明）。

## 三、接口

| 方法/路径 | 作用 |
|---|---|
| `GET /api/components/cfg?s=<会话id>` | 会话配置视图：`{scope, components:{id:{on, values}}}` |
| `POST /api/components/cfg` | 写/删一条覆盖 `{session,id,key,value}`；`value` 缺省或 null＝删这条（回落全局） |
| `POST /api/components/cfg/mode` | 行级 `{session,id,on}`：`on=false`＝跟随全局（删该组件记录） |
| `POST /api/components/cfg/scope` | 总开关 `{session,on}`：`on=false` 清空该会话全部组件配置与启停覆盖 |

- 「跟随全局」时写键被拒（400 并指路先切会话独立）；未知会话/组件 404；
  单条值上限 64KB。
- 四条都登记进 **call_api 可调目录**（读=全电脑只读，写=修改工作区；总开关带
  ⚠ 危险审批，因为关掉会清空该会话的覆盖）。

## 四、自查记录

隔离实例（端口 8799、临时 dataDir、`-webdir web`，不动用户实例），新建一个会话
做端到端：

| 自查项 | 做法 | 结果 |
|---|---|---|
| 基线 | 总开关关时读视图 | ✅ `scope=false`，所有组件 `on=false`；写键被拒（400 提示先切独立） |
| 总开关一键开 | `POST scope {on:true}` | ✅ 全场 `on=true`（缺省独立，值全来自全局） |
| 会话独立时组件读到会话值 | 页面里 `localStorage.setItem('cx:voice:probe','A')` | ✅ 读回 `A`；服务端视图 `voice.values={'cx:voice:probe':'A'}`，别的组件无覆盖 |
| 全局值未被污染 | 打开设置页（bypass）读同名键 | ✅ `null`（会话写没落全局）；在设置页里写 `cx:voice:probe='GLOBAL'` 才是全局 |
| 合并语义 | 关闭设置页后读 | ✅ `probe='A'`（会话覆盖优先）、`gprobe`（只在会话写过）回落为全局/不存在；`jx.probe` 等非组件键完全不受影响 |
| 行级切回跟随全局 | 浮窗里点该行下开关 | ✅ `on=false`、`values={}`，读回全局 `GLOBAL`，小字变「跟随」 |

## 五、验证步骤（用户侧）

1. 重启助手本体进程（本会话跑在旧实例里，我没有替你重启；`jxassistant.exe` 开发版
   已重编）。
2. 打开任一对话 → 输入区加号菜单 →「本对话的组件与插件」：
   - 每行现在是两个开关（上「启用」、下「独立/跟随」）；
   - 底部总开关默认「跟随全局」（下开关禁用）——拨开后全场进入会话独立；
   - 以语音为例：拨开总开关 → 该行下开关为「独立」→ 在浮窗里的语音设置改音色，
     再换一个对话看，那个对话仍是全局音色；
   - 把该行下开关拨回「跟随」→ 本对话立刻回到全局音色（记录已删）；
   - 把底部总开关拨回「跟随全局」→ 每行启停与设置都回到全局。
3. 设置 → 组件 里的全局设置不受影响（打开全局设置页时读写的就是全局值）。

## 六、边界与后续（如实记录）

- 合并层管的是**组件前端偏好**（`localStorage['cx:<id>:*']`）。组件存在服务端的
  **数据/安装级配置**（用户记忆 md、待办清单、市场服务器地址、Git 仓库路径）不随
  会话——它们是数据与全局配置，不是「组件设置」。要让某类服务端配置也随会话，
  得给那条通道单独做合并（机制已备好 `Cfg` 存储，缺的是各通道的读写接线）。
- 浮窗与全局设置页同时开着属于极端情况：此时按 `#settings` 可见即走全局（浮窗里
  的写入也会落到全局），实际使用中两者不会并排操作。
- 会话删除时覆盖随附属数据清理（既有 `forget` + Store 行删除），已有单测覆盖。
