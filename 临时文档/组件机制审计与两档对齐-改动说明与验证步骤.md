# 组件机制审计与「内置 / 用户」两档对齐——改动说明与验证步骤

日期：2026-11-08　范围：`components.go` / `componentbridge.go` / `market.go` /
`update_blocks.go` / `server.go`（call_api 目录）/ `web/index.html` /
`web/app-settings.js` / 组件客户端文案 / 打包脚本 / `.gitignore` / 文档

用户定调的设计：**组件分两条路，面向同一个组件桥**

| | 内置组件 | 用户组件 |
|---|---|---|
| 目录 | `组件/<id>/` | `组件/user/<id>/` |
| 分发 | 随安装包 | 市场 / 发行渠道单个安装 |
| 删除 | ❌ 不可删除，只可开关 | ✅ 可删除 |
| 更新 | 静默更新的「组件分块」热更新 | 不热更新（用户经市场重装） |
| git / 打包 | 入库、进包 | 不入库、不进包 |

---

## 一、现状盘点（改动前）

### 1. 组件发现机制

- 唯一入口：`server.go` 的 `InitComponents("组件", data/components.json)` →
  `rescan()` **只在进程启动那一刻扫一次** 组件根目录下的直接子目录，读
  `manifest.json`（损坏跳过、告警）。
- 之后的重扫只有两处：市场安装/卸载（`Rescan()`）、静默更新组件块应用后
  （`Rescan()`）。
- 桌面版是**单实例常驻**（`desktop_windows.go` 的 `acquireSingleInstance`）：
  再双击只是把已有窗口拉到前面，**不会重启服务进程**。

### 2. user-memory「重启后既不在内置清单、也没有用户入口」的根因（实测确证）

- 现场实例：`坚祥数字助理GO.exe` PID 5556，**进程启动时间 2026-11-06 14:13**，
  监听 127.0.0.1:8788；而 `组件/user-memory/` 的目录时间是 **2026-11-07 15:29**。
- 直接请求该实例 `GET /api/components`：返回 7 个组件（dangerous-cmd-guard /
  git-panel / session-title / sites-platform / skill-market / todo-scheduler /
  voice），**没有 user-memory**——它是在这次扫描之后才出现的，服务端内存里的
  清单再也不会自己更新。
- `data/components.json` 里也没有 user-memory 记录（符合「未记录=缺省启用」
  的读时语义，不是开关问题）。
- 结论：**不是 manifest 写错，也不是归属问题，是发现机制的缺口**——扫描时机
  只有启动一次，而「重启窗口」在本产品里不等于「重启服务」。这也解释了为什么
  上一次会话里「重启或 Rescan 后已实测可见」，到用户手里依旧不见（他重开的是
  窗口，不是服务）。

### 3. 设置页

- 一级页叫「**内置组件**」（`index.html` 的 `data-pane="components"`），页内是
  一个扁平清单 `#component-list`，**没有内置/用户分区**，也没有删除入口；
  组件自己的设置区（`CX.registerSettings`）挂在同一页下方。

### 4. 市场通路

- **有**：`market.go` 的 `installMarketComponent` 已经把 `component` 类型装进
  `a.Components.Dir()`（即 `组件/<id>/`）+ `Rescan()`；卸载走
  `uninstallMarketComponent`，且只允许有市场记账的条目。
- 问题：市场把组件**装进内置区**——与「内置随包、用户装的另放一处」的设计
  冲突；且市场卡片对内置组件也显示「卸载」按钮（点了才在服务端报错）。

### 5. 用户组件的目录约定

- **不存在**。技能有 `技能/user/`，组件没有对应物（`skill_manager.go` 有
  `userSkillsDir()`，组件侧没有）。
- 打包脚本 `打包安装包.ps1` 把 `组件/` 整目录 robocopy 进 stage、升级清理清单
  按 `stage\组件\*` 逐目录重装——**没有排除 user**（一旦有人把用户组件放进
  `组件/user/`，会被打进安装包并在升级时清掉）。

## 二、差距清单（对照设计）

| # | 设计要求 | 改动前 | 处理 |
|---|---|---|---|
| 1 | 两条路、同一个组件桥 | 只有一条路（全部在 `组件/`） | 注册表两层化，worker/钩子/端点/资产/热开关/会话覆盖全共用 |
| 2 | 用户组件独立安装区，不进打包、不上 git、不热更新 | 无目录约定 | 新增 `组件/user/<id>/`（与 `技能/user/` 同款）；`.gitignore`、打包 robocopy、升级清理清单、静默更新发布脚本四处排除 |
| 3 | 内置不可删除、只可开关 | 只能手动删目录 | `POST /api/components/delete` 仅对用户组件生效，内置返回 400 并指路关开关；设置页内置区不给删除按钮 |
| 4 | 用户组件可任意安装/删除/开关 | 市场装进内置区、无删除接口 | 市场安装改落 `组件/user/`；新增删除接口 + 设置页删除按钮；开关同一条热路径 |
| 5 | 市场可单个安装组件 | 有通路但落在内置区、可覆盖内置组件 | 落用户区；同名内置一律拒绝（内置随程序更新，市场不得覆盖）；市场卡片对内置只显示「内置（随程序更新）」 |
| 6 | 内置走热更新、用户不热更新 | 热更新会覆盖同 id 的任何组件 | `planComponentBlocks` 跳过用户组件（版本与去留归用户）；`applyComponentBlock` 只写内置根，且拒绝把 `user` 当块 id |
| 7 | 设置页分区清晰 | 一级页「内置组件」+ 扁平清单 | 一级页改名「组件」，内部「内置组件 / 用户组件」两区（与「技能」页同款排版），用户区带删除 |
| 8 | 用户组件可见（发现机制不能靠重启） | 只在启动扫一次 | 清单接口按需重扫（2 秒节流）：运行中放入/删掉目录刷新页面即见 |

## 三、实现方案

### 后端（components.go）

- 新增 `componentEntry{Manifest, Dir, BuiltIn}`：注册表同时持有**本体目录**与
  **归属**；`items` 由 `map[string]ComponentManifest` 换成 `map[string]componentEntry`。
- `rescan()` 先扫 `组件/`（跳过 `user` 子目录，视为内置），再扫 `组件/user/`
  （视为用户）；**同名 id 内置优先**（用户那份忽略并告警）。
- 新方法：`CompDir(id)`（组件桥锚 cwd / 资产服务用）、`IsBuiltin(id)`、
  `BuiltinDir()`、`UserDir()`、`Remove(id)`（只删用户组件，连开关态一起清）、
  `maybeRescan()`（2 秒节流的按需重扫）。
- `ComponentStatus` 增加 `builtin` 字段（前端分区依据），其余字段不变。
- `handleListComponents` 先 `maybeRescan()`；`handleComponentAsset` 按
  `CompDir(id)` 解析（内置/用户同一条资产路径）；新增 `handleDeleteComponent`
  （`POST /api/components/delete`，内置 400、用户删目录+清开关+清市场记账）。

### 组件桥（componentbridge.go）

- worker 目录从「`Dir()`+id」改成 `CompDir(id)`：两条路的 worker 用同一条拉起
  逻辑，组件自己不需要知道归属。

### 市场（market.go）

- `installMarketComponent` 落 `组件/user/<id>/`；同名内置直接报错（说明内置随包、
  去设置页关开关）。
- `uninstallMarketComponent` 走 `Components.Remove`（只删用户组件）。
- `marketEntryOut` 增 `builtin`，市场卡片对内置组件只显示「内置（随程序更新）」，
  不给安装/卸载（避免点了才报错）。

### 静默更新（update_blocks.go）

- `planComponentBlocks`：本机是用户组件 → 跳过（不覆盖用户手上那版）。
- `applyComponentBlock`：只写 `BuiltinDir()`，且 `user` 不允许当组件块 id。

### 前端（index.html / app-settings.js）

- 一级页「内置组件」→「**组件**」（导航、页标题、各处提示文案同步）。
- 页内两区：`内置组件`（sec-sub：随包分发，不可删除；可开关，随程序更新升级）
  / `用户组件`（sec-sub：可开关、可删除；市场/发行渠道单个安装），分别渲染
  `#component-builtin-list` / `#component-user-list`；用户区行尾是垃圾桶按钮
  （复用 `.skill-del`），删前 `confirmCenter` 二次确认，删后 `CX.refresh()` 热卸载。
- 用户区为空时给虚线占位：「还没有用户组件。在市场里一键安装，或把组件目录放进
  组件/user/ 即装即用」。

### call_api 可调目录（顺带收口）

- `GET /api/components`（全电脑只读）、`POST /api/components`（修改工作区，带
  `session`＝会话级覆盖）、`POST /api/components/delete`（修改工作区 + ⚠ 危险审批）、
  `GET /api/plugins`（全电脑只读）、`POST /api/plugins`（修改工作区 + 会话级覆盖）
  全部登记为 `apiMeta`：数字经理现在能经 call_api 查询与开关组件/插件（含
  `?s=` / `session` 的会话级覆盖）。`TestCallAPICatalogFull` 已钉住这四条。

### 打包 / git

- `.gitignore`：新增 `组件/user/`。
- `打包/打包安装包.ps1`：robocopy 显式 `/XD 组件\user`；升级清理清单跳过 `user`
  目录（用户装的东西升级不动）。
- `打包/发布静默更新.ps1`：`-组件 user` 直接报错（用户组件区不参与热更新）。

### 文档

- `组件/README.md`：开头新增「两档归属」表 + 目录即归属的硬规矩（第 7 条）。
- `AGENT.md`「组件管理」：新增两档归属条目，改写「发现与开关」（按需重扫、
  两个目录、删除接口、call_api 登记），改写「内置与用户的本质区别」（含用户
  组件不热更新）；`user-memory` 段落的「重启才可见」说明改成按需重扫。

## 四、user-memory 归位结论

**判定：`user-memory` 是内置组件**（留在 `组件/user-memory/`，随包分发），不是
用户组件。

依据：

1. 它是产品自带能力（AI 记忆与拟人化），宿主半边 `usermemory.go` 编在引擎里
   （环境提示词注入 + `user_memory` 工具 + `/api/user-memory`），属「组件掌管
   主程序内置功能入口」的既有形态（B 形态套皮，与 todo-scheduler/git-panel
   同类）——它天然随程序版本走。
2. 用户组件的语义是「用户自己装、自己删、版本归用户」；把产品自带能力放进去，
   用户一删就少一个内置功能，且引擎里的宿主半边会变成永远关不掉的死代码。
3. 打包/热更新的语义要求它必须在场：静默更新的组件块能把它带到老客户机器上
   （发布时把 `user-memory` 放进 `发布静默更新.ps1` 的 `-组件` 参数即可）。

结论与用户诉求「哪怕当内置组件出现都该直接出现」一致：改完后它**出现在
设置 → 组件 → 内置组件**，开关即点即热生效。

> 注：`user-memory` 的宿主半边在引擎里，所以它的组件目录缺失时功能整块隐形
> （`userMemoryEnabled` 自查）；这与「内置组件随包必带 + 热更新补装」的规矩
> 配套。发布时要确认 `组件/user-memory/` 进了安装包（打包脚本按
> `组件/*/manifest.json` 统计并强制非空），需要给老客户补装时用静默更新的
> 组件块。

## 六、验证步骤（用户侧）

1. 重启助手本体（本会话就跑在旧实例里，我没有替你重启）：双击 `jxassistant.exe`
   开发版或按既有流程重编安装版；**必须是进程重启**，重开窗口不算。
2. 设置 → **组件**：
   - 「内置组件」区应能看到「AI 记忆与拟人化」，开关一点即热启停；
   - 「用户组件」区此刻为空（虚线占位），说明本机没装用户组件。
3. 装一个用户组件：把任一符合规范的组件目录放进 `组件/user/<id>/`（或从市场
   装一个组件类型的条目），回到设置页刷新即见，行尾有垃圾桶可删。
4. 删内置组件时应当被拒（服务端 400 指路关开关），设置页也不给这个按钮。

## 七、未做 / 后续（如实记录）

- **服务端配合**：市场的「组件」条目分发走现有 `/api/market`（zip 直装，免编译），
  客户端侧已把落点改到用户区；服务端对 `workers/hooks` 声明的校验硬化仍是原有
  待办（与本次两档机制无冲突）。
- **发布参数**：新增/升级内置组件（如 user-memory）时，发布静默更新要把 id 交给
  `-组件` 参数，才会给老客户补装/升级；这一步是发布习惯，未写死进脚本默认值。
- **设置页未做「添加组件」按钮**（技能页那种选文件夹/zip 的入口）：目前用户组件
  的安装入口是市场 + 手动放目录。要补的话与技能页 `install-files` 同款即可，
  本次按 YAGNI 未做。
- **会话级覆盖的残留**：会话覆盖里记着某个已被删掉的用户组件 id 时，注册表会忽略
  它（不会报错），但没有主动清理该会话记录；影响为零（清单里不存在即不生效）。
